# Packaging

How abox is meant to reach users. **Nothing here is published yet**: there is no npm package, no
published AppImage and no tagged release. Until then, install from source as described in
[docs/quickstart.md](../docs/quickstart.md).

| Channel                  | Status                                                                                                             | Where                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| Build from source        | works                                                                                                              | [quickstart](../docs/quickstart.md) |
| AUR `abox-git`           | PKGBUILD written; `bash -n` and `makepkg --printsrcinfo` pass; not built end to end through `makepkg` or submitted | [`aur/`](aur/)                      |
| npm (`@spacy-cloud/...`) | plan only                                                                                                          | below                               |
| AppImage (desktop app)   | builds from source (`pnpm --filter @abox/app dist`) and passes a start smoke test; not signed, not published       | below                               |
| Claude Code marketplace  | marketplace file exists in the repository; works once the repository is public                                     | below                               |

## AUR: `abox-git`

`aur/PKGBUILD` builds the CLI (which contains the MCP server) from the git source and installs:

- `/usr/lib/abox` - a self-contained tree made with `pnpm --filter @abox/cli deploy --prod --legacy`
  (production dependencies only, relative symlinks, so it can be relocated);
- `/usr/bin/abox` - a two-line wrapper that runs `node /usr/lib/abox/dist/bin.js`;
- shell completions for bash, zsh and fish, generated by `abox completion <shell>`;
- the licence, the documentation and the Claude Code plugin in `/usr/share/abox/agent-kit`
  (`claude --plugin-dir /usr/share/abox/agent-kit`).

Build requirements: Node.js >= 24 (`nodejs`), `pnpm`, `git`, a C toolchain and Python (one optional
native dependency of the Docker client library, `cpu-features`, is compiled). The build downloads
the npm dependencies with the lock file (`--frozen-lockfile`); `pnpm` is told not to fetch the exact
`packageManager` version from `package.json`, so the packaged pnpm 10 must be compatible with the
lock file. Optional runtime packages (docker, podman, qemu, libsecret, openssh, ...) are listed as
`optdepends`.

Update `.SRCINFO` after changing the PKGBUILD:

```sh
cd packaging/aur
bash -n PKGBUILD
makepkg --printsrcinfo > .SRCINFO
```

`namcap` was not available when this was written, so the package has not been linted with it.
Versions follow `<cli version>.r<commit count>.g<hash>` until tags exist.

A binary package for the desktop app in the style of `abox-desktop-bin` would wrap the AppImage
once it exists: install the file below `/opt/abox-desktop/`, add a `.desktop` entry and an
`/usr/bin/abox-desktop` wrapper. The app needs the `abox` CLI package only for the terminal, not to
run (it uses the core library directly).

## npm

Planned, **not published**. The name `abox` is taken by another project, so packages will use the
scope **`@spacy-cloud/`** (for example `@spacy-cloud/abox` for the CLI and the `abox` binary). Open
points before a first publish:

- Only `packages/cli` is marked `"private": false`; it depends on workspace-only packages
  (`@abox/core`, `@abox/runtime`, the backends, `@abox/mcp`, `@abox/proxy`) via `workspace:*`.
  Either publish all of them under the scope, or bundle them into the CLI package.
- The package must ship the built-in templates (`packages/core/templates`), the proxy runtime files
  (`packages/proxy/runtime`) and the plugin-independent assets it reads at run time. `pnpm deploy`
  (see above) shows that a self-contained tree works.
- `dist/bin.js` needs the executable bit (the build sets it in a postbuild step), and
  `engines.node` stays `>=24`.
- Releases are tagged with signed tags; npm publishing should use provenance (GitHub Actions with
  OIDC), an automation token kept as a repository secret, and a dry run (`npm publish --dry-run`,
  `npm pack`) that checks the file list.

## AppImage

The Electron app (`packages/app`) is built with `electron-vite` and packaged with `electron-builder`
(a dev dependency; configuration in `packages/app/electron-builder.yml`: app id `cloud.spacy.abox`,
Linux x64, targets AppImage and an unpacked `dir`). It is not part of this directory because it
needs the workspace build, but it is not a plan any more:

```sh
pnpm install && pnpm build
pnpm --filter @abox/app dist     # -> packages/app/release/abox-<version>-x86_64.AppImage (+ release/linux-unpacked/)
pnpm --filter @abox/app smoke    # starts the AppImage under xvfb, checks the window, quits
```

Status: the AppImage builds and the smoke test passes on the development machine. It is **not
signed and not published**, there is no checksum publication yet, and it has not been tried on
other distributions. Things to remember when it ships: the native module `node-pty` is compiled
once against the system Node (it is N-API, so Electron loads it unchanged and it is unpacked from
the asar archive); the AppImage needs FUSE 2 (or `--appimage-extract-and-run`); Chromium's sandbox
needs unprivileged user namespaces (restricted on Ubuntu 24.04 by AppArmor); there is no
auto-update and no telemetry; checksum and signature must be published with the GitHub release.
Details: [packages/app/README.md](../packages/app/README.md#appimage).

## Claude Code marketplace

The repository root contains `.claude-plugin/marketplace.json`, which lists the plugin in
`packages/agent-kit`. After the repository is public:

```text
/plugin marketplace add spacy-cloud/agent-box
/plugin install abox@agent-box
```

Before that, use `claude --plugin-dir packages/agent-kit`. Validate with
`claude plugin validate packages/agent-kit` and `claude plugin validate .` (both pass with Claude
Code 2.1.x). The plugin needs `abox` on the `PATH`, so the AUR package or an npm install is the
natural companion.

## Release checklist (draft)

1. `pnpm build && pnpm test`, plus `pnpm test:docker` and, where possible, the VM tests.
2. Update `CHANGELOG.md` and the per-release list of known limitations in
   [docs/security.md](../docs/security.md#known-limitations-and-not-verified).
3. Bump versions (CLI, plugin manifest, marketplace entry), tag with a signed tag.
4. Publish npm packages, build and upload the AppImage with checksums, create the GitHub release.
5. Update the AUR package (a `-git` package needs no change; a tagged `abox` package would).
